# 分享版使用指南

你得到的是一套本地研究工作台与固定执行规范，不是作者的账号、订阅或私人资料。每位使用者在自己电脑运行一份，使用自己的 Codex 或 API。当前分享流程面向 Windows；其他系统尚未提供等效的双击安装与媒体验收。

## 1. 下载与首次安装

1. 从已获授权的 GitHub 仓库克隆／下载，或接收作者提供的源码 ZIP。仓库为 Private 时，仅有链接不代表有访问权。
2. 完整解压到自己有写权限的位置，保留 `.agents/`、`config/`、`assets/`、`web/`、`scripts/`。不要只保存网页 HTML，不要在 ZIP 内直接启动，也不要放到只读系统目录。
3. 安装 Python 3.9 或以上（推荐 3.12，与项目 CI 覆盖版本一致）。让 `python` 或 Windows 的 `py` 启动器可用；无需作者的 Anaconda。下载入口为 [Python 官方网站](https://www.python.org/downloads/)。
4. 双击根目录 `首次安装.cmd`。它调用 `setup.ps1`，创建此项目专用 `.venv` 并下载 `requirements.txt` 中的依赖。也可在项目目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1`。
5. 安装完成后双击 `启动论文开讲.cmd`，浏览器打开 `http://127.0.0.1:7860/`。先点“先看看成品示例”检查界面，无需 API Key；示例不是真实研究，也不会合成语音。

这是源码版，不是免安装 EXE。不要复制作者或其他电脑的 `.venv`。首次联网安装受网络和系统权限影响，失败时阅读窗口中的报错，不要通过禁用 TLS 或防火墙来绕过。

## 2. 使用自己的 Codex

1. 在支持本地文件访问的官方 Codex 客户端中，登录自己的 ChatGPT 账号。可用额度和权限取决于自己的账号／工作区，不使用作者的额度。
2. 将解压／克隆后的本项目目录设为本地项目的**主目录**。主目录应直接包含 `AGENTS.md`；不是 `.agents` 子目录，也不是另一份空文件夹。
3. 在网页上传材料，选择读者基础与制作偏好，保持“Codex 接力”，点击“保存任务并交给 Codex”。
4. 将网页生成的整段指令复制到**同一份本地项目目录**里的 Codex 对话，提交执行。按需要授权读取材料、写入产物及联网检索／语音合成。
5. 保持网页打开，页面会读取本地任务文件并更新进度。完成后在“研究记录／当前任务”查看报告、脚本、音频和按需动画。

首次可以发给自己的 Codex：

> 请确认当前目录是 paper-dialogue-studio 的项目根目录。先读取 AGENTS.md，检查项目依赖和 $paper-dialogue-podcast 是否可用。不要处理示例或自动调用付费 API；说明就绪情况，等我提交网页任务指令。

仓库自带 `.agents/skills/paper-dialogue-podcast`，不需要复制作者电脑的个人技能或登录文件。官方说明：Codex 可通过 ChatGPT 登录获得订阅访问，或通过 API Key 使用按量访问；项目主目录用于发现规范，仓库级技能放在 `.agents/skills`。[OpenAI Docs：认证](https://learn.chatgpt.com/docs/auth)、[本地项目](https://learn.chatgpt.com/docs/projects)、[技能发现](https://learn.chatgpt.com/docs/build-skills)。核对日期：2026-11-07。

注意：这里没有“网页登录 Codex 后自动调用订阅”的实现，也不收集 ChatGPT 密码、Cookie 或 Codex 登录缓存。不要把登录凭据发给作者。普通 ChatGPT 网页聊天若没有本地目录访问，不能仅凭任务 ID 读取你电脑上的文件。也不要另开一个没有 `inbox/` 材料的 Git worktree／云端仓库副本来处理该 ID。

## 3. 使用自己的模型 API

1. 在模型提供方开通 API 并获取自己的 Key，确认可用模型、余额和费用规则。
2. 网页“生成方式”切换到“API 自动制作”，打开“API 连接设置”。填写 Base URL、模型 ID、API Key；配置属于本机服务，不会使用作者的 Key。
3. 点击“保存本次设置”，可测试模型列表连接。返回主页面，明确同意材料传输与按量计费后提交。
4. 网页自动执行，不需要 Codex。失败时保留原因和缓存；不要反复提交新任务来掩盖余额、权限或上下文问题。

当前实现面向 HTTPS 的 Chat Completions 兼容接口，要求模型支持 JSON Mode 等实际请求参数。Kimi 是预设之一，不保证所有“兼容 API”或模型都能直接运行；模型 ID 以自己账户的可用列表为准。只支持 Responses 的接口或需要不同认证的服务，不能仅换一个地址使用。本机模型地址当前被安全策略拒绝。

测试连接仅查询模型列表，不代表付费生成、长文解析或音频已验收。API 使用自己的提供方计费规则，不会自动借用 Codex 订阅额度。音频仍走单独的 Edge 语音模块，文本模型 API 不负责声音。详见 [API 使用与边界](API.md)。

## 4. 文件、密钥与联网范围

- `inbox/` 保存原始材料与任务；`outputs/` 保存研究底稿、报告、脚本和音频，均在自己的电脑，默认被 Git 和源码打包排除。
- 本地保存不等于完全离线：Codex／所选模型服务会处理授权发送的材料；语音文本会发送到 Edge 在线语音服务；读取 Notion 和公开原文也需要联网。敏感材料须先确认自己的权限及相应服务政策。
- 网页填写的 Key／Notion Token 在当前本地服务进程内存中保存，不回显、不写进任务或浏览器存储。可选 `.env` 是明文文件，只能留在本机；不要分享、截图或提交它。
- 私有 Notion 需要使用者自己的授权连接，或自己的 Integration Token，并把目标页面共享给该 Integration。作者的 Notion 权限不会随源码传递。
- 公开研究结果前自行检查材料版权、个人信息和语音服务使用条件；软件 MIT 许可不等于对文献、第三方服务或声音的授权。

所有网页关闭后约 40 秒退出本地服务，API 任务随之停止；已发出的请求仍可能计费。Codex 对话独立运行，不会随网页关闭自动取消。再次双击启动文件恢复查看，直接点击旧 localhost 地址不能唤醒已退出的服务。

## 5. 更新与常见问题

- **任务找不到**：确认网页和 Codex 使用同一份目录，不是两次解压的两个副本。不要只发任务 ID 给没有该目录权限的聊天。
- **找不到 Python**：确认 `python --version` 或 `py -3 --version` 可用；也可将 `PODCAST_PYTHON` 设为自己安装的 Python 可执行文件路径后再运行安装脚本。
- **网页打不开**：运行启动文件，检查是否安装完成、端口 7860 是否被其他程序占用。不要把地址换成公网监听来解决。
- **模型列表成功但生成失败**：核对模型的 JSON Mode、输出长度、上下文、余额与服务错误；测试列表不验证这些。
- **只有文本、没有音频**：检查是否勾选人声以及任务阶段／错误。语音需要联网；演示不生成音频，无法保证第三方在线语音始终可用。
- **更新源码**：先停止 API 制作并关闭网页，备份自己的 `inbox/`、`outputs/` 和本地配置。Git 用户检查本地差异后拉取；ZIP 用户保留原目录，解压新版本后谨慎迁移数据和个人配置。不要用别人的运行环境覆盖 `.venv`，依赖变更后重新执行首次安装。

## 6. 为什么不直接发一个公网网址

当前服务只绑定本机，且没有多人登录、任务归属鉴权、用户级密钥隔离或存储配额；同一服务进程共享 API 设置。因此它适合“一人一份本地运行”，不适合直接加反向代理、内网穿透或开放端口给多个人使用。GitHub Pages 也不能运行本项目的 Python 后端。

如果以后需要真正的多人在线版，应另行设计认证、任务／文件／密钥隔离、HTTPS、队列、配额、日志脱敏和数据删除；让远程网页与每个人本地 Codex 接力也需要额外的安全连接机制。这不在本次分享包中。
