# API 自动制作

## 使用方式

网页“生成方式”选择“API 自动制作”，然后填写 Base URL、模型 ID 和 API Key。Kimi 默认地址为 `https://api.moonshot.cn/v1`，模型 ID 默认 `kimi-k3.1-pro`；可按账户实际可用模型修改，参考[官方快速开始](https://platform.kimi.com/docs/get-api-key)。

点击“测试连接”只请求模型列表，不发送论文或执行生成，因此不能证明余额、长文生成及声音质量正常。正式提交前需勾选“同意发送材料并了解按量计费”。每次只运行一个 API 任务，避免误触并发生成。

页面输入的密钥仅保存在当前服务进程内存中，保存后输入框清空，接口不回显；不放入浏览器存储、任务或输出目录。更换 Base URL 会清除旧模型密钥，需重新填写。不要把密钥写在问题、文章或自定义基础中。

如需重启后保留配置，可复制 `.env.example` 为本地 `.env`，手动填写。`.env` 是明文凭据文件，已被 Git 和打包脚本排除，应限制本机访问；不要截图或上传。系统环境变量优先于 `.env`。网页“清除内存密钥”不删除 `.env`，重启时仍会重新读取文件。

## 流程与实际范围

1. 提取上传的 PDF 文本／HTML 正文，或下载链接正文。检查低文本页、缺失内容；扫描件需要先 OCR 或交给 Codex。
2. 从实际材料识别论文，再查询 arXiv。候选先核对标题与作者，获取原文后才允许作为已读取来源；所有尝试落在 `api-searches.json`。当前自动检索仅覆盖 arXiv，不代表查遍期刊、PMC 或机构仓库。其他合法原文可作为补充链接输入。
3. 生成 `research.json`；证据原句必须在实际提取的位置匹配，所有来源标为 `text_only`。原句匹配和字段验证不能证明论断逻辑正确。
4. 分章写稿，遵循读者基础、深度、讲解方式、形式与时长；共用验证器派生报告、脚本、学习卡和按需 HTML 动画。
5. 再做一轮逐条论断与脚本的模型文本复核。未通过则保留诊断，不发布；通过也不代表独立专家或人工审核。
6. 需要音频时，仍由独立的 Edge 语音模块制作小样和成片，执行解码、实测时长、角色与哈希检查。Kimi 负责文本，不负责本项目的人声。没有实际听取就不记录为听感通过。

输入上限为 350,000 个提取字符、最多 12 篇待识别主论文；过大时停止并提示拆分，不静默截断。上下文是否足够还取决于所选模型。当前不做图片视觉理解、自动 OCR、ASR、外部实验或 MP4 渲染；缺少关键图表而不能核验主要结论时，应停止交付并补资料。

API 来源下载只允许公网上的 HTTP(S) 80/443，阻止内网、localhost、URL 内账号密码及不安全跳转。API 地址本身必须 HTTPS；不支持把此入口直接指向本机模型服务。网络请求不使用系统代理，受限网络可能需要调整网络环境，不能通过关闭 TLS 验证解决。

## Notion

公开页面可尝试直接读取。动态页面正文不可得时，导出 HTML/PDF，或填写 Notion Integration Token 并把目标页面共享给 Integration。API 模式读取页面文本块、嵌套块、列表和表格文本；不把图片、嵌入 PDF、子页面或数据库当作已经阅读。Token 仅发往固定 Notion API，不能替代页面访问授权。

## 费用、停止和继续

- [Kimi API 按量计费](https://platform.kimi.com/docs/pricing/chat)，不消耗 Kimi/ChatGPT/Codex 会员配额。其他兼容提供方以各自政策为准，没有“开源模型 API 一定免费”的保证。
- 默认每次运行最多 32 次模型请求，范围 4–80；包括限流／服务错误重试。调用次数上限不是金额上限，重试任务会重置本次计数。请同时在提供方设置账户预算。
- 缓存以提示词、模型、提供方和规范绑定；修改这些内容后相应阶段可能重新计费。结构纠错最多三次，不接受截断 JSON。
- “停止 API 任务”停止后续阶段。已有 HTTP 请求可能要等待返回；提供方是否计费无法撤销。所有页面关闭后，网站在宽限期结束时退出，后台不会无限运行。
- 意外中断后不自动恢复付费请求。重开网页、配置密钥、确认继续，复用可验证的阶段缓存；失败任务与历史成片都保留。
- Codex 接力保持独立；不得把已有 Codex 任务自动改成 API 任务。需要 Codex 接手 API 失败产物时，先停止 API，再把任务 ID 和问题交给本项目中的 Codex 对话。

`api-run.json` 记录模型和请求 usage，不包含密钥；`api-content-review.json` 记录模型复核，`release.json` 标明 `reviewer: api_model`。这些材料可能含私人研究内容，均留在已排除发布的 `outputs/` 中。
