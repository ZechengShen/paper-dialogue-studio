# 专业精读协议：读懂、质疑、重建、教会

本协议是本项目自行设计的执行规范，不是任何博主的逐字课程，也不以“扮演专家”代替学科知识。每次运行要填写论文相关的实际判断、证据定位和未知项，不能把问题清单本身当作分析完成。

## 参考来源及核验边界

2026-10-24 核验：

- [李沐官方论文精读目录](https://github.com/mli/paper-reading)：确认其包含逐段精读、主题串讲及按数据／模型／训练拆分的系列。借鉴颗粒度和教学组织；本次未取得视频完整字幕，不归因具体话术、时间戳或逐段讲解内容。后续选 1–2 个可访问实例建立样例卡后再细化。
- [S. Keshav：How to Read a Paper](https://systems.cs.columbia.edu/ds2-class/papers/keshav-paper.pdf)：借鉴先建立全貌、再理解内容、最后尝试重建的分层阅读，保留每遍结束后的继续／补课／暂停决定。
- [NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist)：借鉴主张与证据匹配、假设、限制及可复现性检查；它是 AI 研究检查清单，不作为所有学科通用质量认证。
- [Alex Wang：You could have invented transformers from memory](https://alexwang.ai/posts/associative-memory/)（2026-10-15）：核验到原文及推导。借鉴从记忆任务出发，以检索干扰为瓶颈，逐步引入线性、非线性和注意力机制的解释视角。该文的容量讨论基于特定简化条件，不能直接替代真实模型的知识容量测试。
- [Gwern：You Could’ve Invented Transformers](https://gwern.net/blog/2025/you-could-have-invented-transformers)：借鉴“教学性重建”与真实发现历史的区分。

下列问题库、字段、门禁与跨学科规则是本项目的综合设计，不宣称以上作者逐条提出或认可。

## 0. 建立能力边界

先确定研究问题、读者基础、论文类型与必要先修知识。列出陌生术语、关键技术、需要补读的原始文献。能查证则补齐；不能理解的关键推导明确标为未核验。不要凭文章流畅度或机构名气判断正确性。

第一遍同步核查论文署名与脚注：第一／共同第一作者、明确指定的通讯作者、作者与论文发表时单位的对应关系、年份及预印本／期刊状态。保存能定位的证据；缺失身份如实写未确认，不能从作者排序猜测。作者背景只选择与本研究有关且有来源的贡献。将这些身份信息与研究目标、方法、结果、边界写入 teaching.opening，先建立听众的知识起点。

工作中顺序切换四个视角：研究者重建最佳版本的论证；审查者寻找反例和替代解释；教师设计学习路径；校对者检查数字、引文、单位与跨产物一致性。这是同一研究过程的检查步骤，不等于多名独立专家审稿，也不默认启动子代理。

## 1. 三遍阅读，每遍都交出东西

| 遍次 | 要完成的工作 | 必须保留的判断 |
|---|---|---|
| 全景定位 | 标题、摘要、问题、结论、结构、关键图表与引用关系 | 研究什么；旧方案是什么；作者声称新在哪里；与本次问题相关吗；继续还是先补课 |
| 论证与证据 | 全文阅读地图；方法输入输出；核心图表逐项解读；关键论断绑定原文 | 作者怎样从问题走到结论；哪些证据还读不懂；论断是否超出实验或证明 |
| 技术重建与挑战 | 关键公式／算法／实验重建；假设和反例；替代路线；最小验证计划 | 能否解释每一步为何需要；怎样证伪；哪些地方仍未知；是否实际运行过 |

deep 原则上完成三遍。无法完成时保留 partial/skipped 和原因；brief 可以有意识地停在前两遍，不能宣传为全文精读。重要证明不能因为难就静默跳过。补读先围绕当前缺口，不无限扩展书目。

## 2. 八类专业追问

每篇至少记录八类问题的实际回答；不适用写理由。回答有证据就引用 evidence_ids，没有则标 open，不能为了填满表格编造。

| 分类 | 核心追问 | 深一层的追问 |
|---|---|---|
| problem | 不使用作者的新术语，问题到底是什么？ | 谁遇到这个限制？它是科学未知、工程约束还是评价方式的问题？ |
| novelty | 相比最接近的工作，改变了哪个关键变量？ | 是新的机制、规模、数据、组合还是执行改进？新与有用分别有何证据？ |
| method | 为什么这个设计能针对问题？ | 如果拿掉该组件会怎样？有哪些更简单的可行替代？ |
| evidence | 哪个图／表／定理真正支持核心结论？ | 它排除了哪些解释，又没有排除哪些？统计差异是否有实际意义？ |
| alternative | 是否存在同样解释结果的其他机制？ | 数据、参数量、算力、筛选、评测流程是否混在改动中？ |
| boundary | 结论在什么假设、样本与场景下成立？ | 哪个反例或条件变化会使结论不成立？ |
| reproduction | 仅凭材料，能否重建最关键的一步？ | 缺少哪些参数、代码、数据或隐含操作？先验证哪个最小现象？ |
| next_step | 最值得减少的一个不确定性是什么？ | 什么结果会改变当前判断？最小成本的区分性检验是什么？ |

针对每个主图：问题→变量和单位→样本／对照→观察→支持的论断→不能推出什么。误差线只说明对应定义下的不确定性，不能自动等同于统计显著或因果。

针对关键公式：符号及维度→假设→每一变换理由→极端情况／小例子→公式在论证中的用途。无法核验的推导保留疑问，不以类比取代数学。

## 3. 按论文类型审查

- 实证／AI：数据来源与划分、泄漏、基线公平性、训练与推理预算、消融、重复运行及不确定性、分布外表现。没有某项并不自动判错；说明其对具体主张的影响。
- 理论：定理量词与适用范围、全部假设、关键引理、证明缺口、必要／充分条件、有限样本与渐近条件、反例。
- 系统：工作负载、硬件软件版本、吞吐与尾延迟、资源成本、故障模式、测量口径、端到端与局部加速区别。
- 综述：检索范围和截止时间、纳排标准、重复研究、分类合理性、异质性与发表偏差。不因有多篇引用就声称完成系统综述或元分析。
- 物理／实验科学：控制变量、测量与校准、误差传播、参数范围、替代物理机制、模拟与实验对应、可观测量和推断量的区别。
- 评论／方法文章：论点、例证、前提、选择性举例、未经实验验证的建议。不要硬填“样本量／显著性”。

混合论文可组合多个检查组。在 technical_audit 记录 supported/unclear/concern/not_applicable、理由与证据，而非看似精确的总分。

## 4. 建构式理解：假如从零开始设计

每篇技术论文尝试一条可能的设计路径，适用范围不足则说明原因，不强求推导出整套技术。

固定结构：目标与约束 → 朴素可行方案 → 可展示的失败例子／瓶颈 → 最小改动 → 可检验预测 → 新代价／新边界 → 与作者方案对照。

每一步必须回答：为什么需要这次改动？解决了什么而没有解决什么？还可以走哪条路？怎样检验解释？可以先预测再展示论文结果，但不能假装真的没有读过结果。

三类标签不可混淆：

- source_supported：作者明确写出的设计动机或证据支持的关系。
- derived：在列出的假设下，可以检查的数学推导／计算。附推导过程。
- hypothesis：帮助理解的可能路径或尚未验证的机制。列出如何检验。

新技术允许保留“目前只能重建到这一步”。没有证据时不说“唯一合理方案”“必然如此”或“作者当时就是这样想的”。教学重建、历史叙述、机制证明是三种不同产物。

技术理解的验收不是故事顺畅，而是能提出反事实预测：删掉组件、改变尺度、换数据分布、打破假设后预计什么会变化？解释不了的地方进入 unresolved 和 followups。

## 5. 多篇研究与教学转译

先逐篇完成独立判断，再比较问题、对象、数据、指标、假设、预算与证据强度。将“相互支持”“真正冲突”“测量不同所以不可直接比较”分开。不能对异质结果直接平均或作排行榜。需要时建路线图：共同瓶颈→各自方案→代价→尚缺的区分性证据。

双人脚本不照着检查清单念。每章选一个真实认知障碍：提问→先猜一个简单答案→看反例→引入机制→回到证据→迁移小题。学习者负责暴露误解、提出替代、检查边界，不只说“明白了”。主持人允许说“这一步论文没有回答”。

动画优先画变化：朴素方案在哪里失败、改动消除了什么、代价在哪里出现。每屏一个认知动作；不把所有模块同时堆满。默认生成逻辑链步进示意；只有具备方程与数据时才做定量模拟。不能用装饰运动冒充机制解释。

## 6. 内容复核门禁

完成前检查：核心结论均可定位；数字／单位／比较口径一致；关键公式的假设可见；作者主张与教学推断分开；至少能解释一个替代方案或不适用理由；未解决的问题没有在脚本里被说成已解决。

review 的结构通过不代表科学内容通过。release.json 必须说明复核范围、仍存限制和对当前 research.json 的哈希绑定。不能仅因为代码验证成功就填写 scientific_review=passed。

## 后续学习范例的规范

新范例用样例卡保存：作者原始链接、可访问的字幕／原文位置、观察到的教学动作、解决的认知障碍、可复用的抽象规则、适用边界。只从实际读到的内容归纳；网友转述用于找线索，不能假装是原作者原话。不复制长段脚本，不模仿作者声音，也不借名人背书替代证据。
