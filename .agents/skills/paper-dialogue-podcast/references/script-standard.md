# 教学播客与资讯简报脚本标准

V3 补充：按照 expert-reading.md 将专业追问转化为认知推进。必要时用“朴素方案→失败例子→最小改动→新代价→证据”的建构式理解路径；明确它是教学重建，不是真实发明史。不能把未知机制写成确定的解释。每个实质轮次绑定 research.json 的 claim_ids。正文只能有一次全片最终总结，章节回顾须推进新问题，不为凑时长重复审计。

## 选择节目形式

- `dialogue`：单篇和多篇研究的默认形式，围绕共同问题推进理解。
- `single_narrator`：用户指定时使用；适合克制的研究资讯简报。
- 用户明确指定单人或双人时，覆盖默认形式。

两种形式的第一轮都必须披露音频由 AI 生成，不是真人录音或作者访谈。

## 双人教学对话

先在 research.json 的 teaching.beats 保存逐章的具体问题、例子、预测与迁移自测。采用“用自己的话解释→提出可检验预测→回到原文补缺口→用新例子再解释”的学习闭环；此为项目操作化方法，不宣称费曼正式发表过这个四步算法。参照 3Blue1Brown 时学习问题与画面如何配合，不模仿其声音或照搬脚本。

- `host`：沉着、清晰、重视推理边界的主讲。
- `learner`：聪明但不假装懂的提问者，通过追问、质疑和复述推动理解。
- 单篇脚本按“困惑 → 旧解释 → 缺口 → 假设 → 方法理由 → 证据 → 边界 → 替代解释 → 含义”推进。
- 每章至少包含一次实质性问题、一次自己的话复述，以及一次证据或边界检查。
- HTML 精读稿要自然区分“精读者这样概括”和“回到原文可以确认”。
- PDF 要覆盖逐段分析中筛出的全部关键论证节点，不按页码机械朗读。

## 单人资讯简报

- `narrator`：一位冷静、自然、信息密度高的播报者，不模仿突发新闻腔。
- 开场用 30–60 秒交代本期汇总主题、论文数量和选择范围。
- 每篇论文独立成章，固定回答“背景是什么、问题是什么、逻辑怎样推进、具体做了什么、得到什么结论”。
- 在相邻论文之间用一句关系过渡，说明补充、对照、分歧或方法差异。
- 结尾只总结跨论文共识、分歧与一个最重要的开放问题。
- 不为制造对话感虚构第二个人，也不把每篇论文压缩成一句标题摘要。

## 通用口播要求

- 每轮通常 35–180 个汉字；单人简报的解释轮可放宽至 220 字。
- 不在 spoken `text` 中写舞台指令、Markdown、引用编号或 URL。
- 公式改为可听懂的口语解释，在 `source_refs` 保留位置。
- 只使用配置中的 `delivery` 预设。
- `pause_ms` 通常为 260–850；章节转换可为 900–1300。
- 不用重复摘要填充时长；扩展内容必须来自背景、方法理由、证据或逻辑关系。
- 中英混排以等效口播单位进行粗筛，最终用短样本／同参数历史与成片实测检查时长；配置默认容差为 12%。原始字数不能冒充准确时长。
- 原稿负责事实与教学逻辑，不为照顾某个语音模型而写谐音字。缩写、符号和术语读法由 `config/pronunciation.yaml` 与人声导演 V2 处理。
- 用正常标点表达逻辑结构；合成前由人声导演把较长轮次拆成可表演短句，并保留与原轮的对应关系。
