# 论文精读与多篇汇总标准

## 先判断内容模式

文件类型是先验，不是结论。先识别材料实际覆盖的主要论文数量：一篇论文只有一个中心研究对象；两篇以上论文必须能分别识别题名、作者、DOI/arXiv 或明确引用，并且材料对它们有实质性讨论。只有顺带引用不算一篇主要论文。

记录 `analysis_mode`：

- `single_paper_close_reading`：原始论文为主，常见于 PDF。
- `commentary_plus_original`：输入是单篇论文的中文精读、批注或解读，常见于 HTML；必须与原文交叉核验。
- `multi_paper_research`：两篇以上主要论文的默认模式，逐篇深读后围绕共同问题综合。
- `multi_paper_briefing`：仅在用户明确要求简报时启用，不能因来源为 Notion 自动降级。

若扩展名与内容冲突，以内容为准，并在 `reading_caveats` 说明判断。

## PDF 单篇：逐页逐段精读

1. 先通读全文并建立章节、页码、图表、公式和附录地图。
2. 按原文顺序检查每个实质段落，记录它在论证中的功能：背景、问题、缺口、假设、方法、结果、解释、限制或过渡。
3. 不要求在口播中机械朗读每段；必须把所有重要段落纳入分析，再按逻辑重新组织脚本。
4. 用页码、章节、图表和公式定位关键证据；不能只依赖摘要与结论。
5. 自动时长使用 30/45/60 分钟：短而单一为 30，完整实证为 45，理论、方法或证据链复杂为 60。

## HTML 单篇精读稿：解读与原文交叉

1. 把 HTML 视为精读者的解释层，不自动视为论文原文。
2. 从 HTML 提取论文身份、核心观点、段落结构、引用、链接和精读者的推断。
3. 尽力取得合法公开原文或作者版本，并以原文核验事实、数据、方法与结论。
4. 分开标记“精读稿提供的信息”“论文原文支持的内容”和“Codex 的补充推断”。两者冲突时以原文为准并说明差异。
5. 脚本按精读稿提供的理解路径逐步展开，但关键断言必须回到原文位置。
6. 自动时长使用 30/45/60 分钟。

## 多篇研究：先逐篇，后比较

对每篇主要论文分别建立 `papers[]` 条目，至少讲清：

1. 身份与背景：谁在什么语境下研究什么问题，为什么值得关注。
2. 逻辑链：已有认知或现实困惑 → 缺口 → 研究问题或假设 → 方法选择。
3. 做了什么：数据、实验、模型、材料或分析动作；不需要展开与结论无关的技术枝节。
4. 发现了什么：主要证据、结论和最必要的边界。
5. 与汇总主题的关系：它补充、支持、修正还是挑战了其他论文。

默认完成 expert-reading.md 的专业追问与技术审查，最后围绕共同问题比较数据、指标、假设、预算和边界。不可比之处单列。仅在简报模式压缩审查深度；不能把未核验内容说成定论。

深读默认 45/60 分钟，过长先规划分集。简报按主要论文数量选择：2–3 篇约 15 分钟，4–6 篇约 20 分钟，7 篇以上约 30 分钟并优先保留主线。用户明确指定时长时服从用户。

## 通用证据纪律

- 记录题名、作者、年份、期刊或会议、DOI、arXiv ID与来源位置。
- 分开标记 `author_claim`、`paper_evidence` 和 `codex_inference`。
- 不虚构样本量、系数、显著性、引文或公式。
- 无法辨认的页面、公式、图表或缺失原文必须列入 `reading_caveats`。
- 公开版本必须核对题名、作者、年份与 DOI/arXiv 身份；只列合法来源。
- 先给小白可理解的全景，再解释“为什么下一步必须这样走”。
